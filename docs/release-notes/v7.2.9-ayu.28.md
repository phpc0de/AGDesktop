# v7.2.9-ayu.28

应用代码与 v7.2.9-ayu.27 完全一致（无功能变化），本版只修复外部构建机的 Libraries 准备流水线：jom 阶段静默失败导致 prepare 在 openssl3 报 'jom' is not recognized。

## Internal
- prepare 的 jom 阶段硬化：下载换 curl（失败即报错并重试）、解压显式指定目标、并加 jom.exe 存在性硬检查——坏下载在第 5 阶段就地失败，不再把故障拖到 openssl3 才以费解的形式暴露（0b4e1983cf）。
- msys64 / NuGet / rustup 三处下载同样换 curl，与 jom 同一模式；CI 重跑改为 silent 续跑失败阶段，不再撞 CI 无法应答的交互提示（6407c2356d）。
- CI 缓存 key 不再 hash prepare.py：真正的失效判定由每阶段 cache_keys 承担，此后改脚本只重建受影响阶段，不再触发全量重建；失败摘要改精确 token 匹配，不再把 libgpg-error 包名与 msbuild "0 Error(s)" 当错误（6dee5175cf）。
- 本次 key 变更使本次构建为最后一次全量重建，此后进入增量模型。
