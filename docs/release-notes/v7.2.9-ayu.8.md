# Release Notes — v7.2.9-ayu.8

Base: upstream v7.2.9 + AyuGram dev. Tag: `v7.2.9-ayu.8` (head `b0737ee9b3`).

## Added

- **MTP Devtools real TL decoding** (replaces hex-only dump):
  - Scheme table generated from `api.tl` + `mtproto.tl` (2345 constructors,
    `Telegram/SourceFiles/ayu/debug/mtp_scheme_table.h` via
    `gen_mtp_scheme_table.py`).
  - Detail pane renders packets as an indented TL tree; unknown
    constructors degrade to raw hex instead of failing.
  - `user_id` / `chat_id` / `channel_id` fields annotated with the
    resolved peer name; `file_reference` and other `bytes` fields shown
    as readable hex; strings unescaped.
  - List rows show the real constructor name (transport envelopes
    `message` / `msg_container` / `rpc_result` are unwrapped).
  - New codec pair: `ayu/debug/mtp_tl_codec.{h,cpp}` (decode + re-encode).
- **Edit & Replay rewrite**: editing opens the decoded TL tree; flags
  bits are recomputed automatically from which optional fields are
  present, then the packet is replayed. Replay and edit-replay log
  done/fail to `[mtpdev]`.
- **Show unavailable channels** setting (AyuGram Settings → Filters):
  bypasses the "violated ToS" banner for restricted channels locally.
- **Raw Console tooltips and dialogs**: all devtools buttons have
  descriptions; Replay / Edit & Replay are disabled on rows where they
  cannot apply (responses, errors), with an instruction header inside
  the TL editor.

## Changed

- **Zero-cost forward (unlock noforwards) rebuilt on raw MTP**:
  - Albums are grouped by `groupId` and sent as one
    `messages.sendMultiMedia` call, so a forwarded album stays one album.
  - No more optimistic local inserts: messages appear only after the
    server confirms (`applyUpdates` in the `done` handler), so failed
    sends no longer leave spinner ghosts that vanish after restart.
  - Per-unit `done` / `fail` logging (`zerocost media ok/FAILED`,
    `album ok/FAILED`, `fallback full items=N`); `sent` counts only
    server-confirmed messages.
  - Automatic full fallback (download + re-upload) for any rejected
    unit, so forwarded content is always persisted.
- **Devtools selection stability**: clicking a row pins the detail pane;
  incoming live traffic no longer switches the content under the cursor.
  A `Hex` toggle shows the raw 32-bit words when needed.

## Fixed

- **Folder tags toggle reverted itself**: server responses
  (`messages.getDialogFilters` → `tags_enabled=false`) overwrote the
  local forced setting on every reload; the forced value now OR-s with
  the server value and can no longer be turned off remotely
  (`data_chat_filters.cpp`).
- **Forward of a single album split into separate messages** (see
  Changed above).
- **Forwarded videos spun forever and disappeared after restart**
  (see Changed above).
- **Devtools `core_message` / `ERROR_SCHEME_BAD_CONS` dump failures**
  (see Added above).
- Self-review pass over the new code: `Api::EntitiesToMTP` argument type,
  `mtpc_boolTrue`/`mtpc_boolFalse` constants, a null dereference in
  album grouping when the previous unit was a text item, missing
  `<QtGui/QFontDatabase>` include, dead helper removed.

## Known Limits

- `CHAT_FORWARDS_RESTRICTED` on media references is enforced server-side;
  zero-cost copying of protected media cannot be bypassed by the client.
  The client now tries the zero-cost path first and falls back to a full
  re-upload automatically when the server refuses.
- The ToS-banner bypass is a local display change only; the account is
  still bound by the same server-side restrictions.
